## 1. The Big Picture

Before touching any code, understand this simple flow:

```
Browser/Phone
     │
     │  HTTP Request: "Give me course data" + JWT token
     ▼
  Nginx (frontend container)
     │  /api/* → forward to backend
     ▼
  Gunicorn (runs Django)
     │
     ├──► URLs.py        "Which view handles this URL?"
     ├──► Permissions    "Is this user allowed?"
     ├──► View           "Do the logic"
     │       │
     │       ├──► Model      "Read/Write the database"
     │       ├──► Redis      "Check the cache first"
     │       └──► Serializer "Convert Python objects → JSON"
     │
     └──► JSON Response back to the browser
```

**Think of it like a restaurant:**
- **URL** = the menu (what you can order)
- **View** = the cook (does the work)
- **Model** = the storage room (holds all the data)
- **Serializer** = the plate (presents the food nicely)
- **Permission** = the bouncer (you can only enter if you belong)

## 2. Models

### What is a Model?

A **Model** is a Python class that represents a **database table**. Each attribute = one column. Django converts it to SQL automatically.

```python
# This Python class...
class Student(models.Model):
    name = models.CharField(max_length=100)
    student_id = models.CharField(max_length=20)

# ...becomes this SQL table:
# CREATE TABLE students (
#     id INTEGER PRIMARY KEY,
#     name VARCHAR(100),
#     student_id VARCHAR(20)
# );
```

```python
class Session(models.Model):
    course           = ForeignKey(Course)
    professor        = ForeignKey(Professor)
    semester         = ForeignKey(Semester)
    date_time        = DateTimeField(auto_now_add=True)
    qr_token         = CharField(unique=True, db_index=True)
    qr_expires_at    = DateTimeField()
    end_time         = DateTimeField(null=True, blank=True)
    duration_minutes = FloatField(null=True, blank=True)
    teacher_note     = TextField(blank=True, default='')

    def save(self, *args, **kwargs):
        if not self.qr_token:
            self.qr_token = str(uuid.uuid4())
        if not self.qr_expires_at:
            self.qr_expires_at = now() + timedelta(minutes=15)
        super().save(*args, **kwargs)

    def record_end(self, timestamp=None):
        self.end_time = timestamp or now()
        delta = self.end_time - self.date_time
        self.duration_minutes = round(delta.total_seconds() / 60, 1)
        self.save(update_fields=['end_time', 'duration_minutes'])
```

```python
class Attendance(models.Model):
    session    = ForeignKey(Session)
    student    = ForeignKey(Student)
    course     = ForeignKey(Course, null=True, blank=True) # Denormalized for query speed
    date       = DateField(auto_now_add=True)
    scanned_at = DateTimeField(auto_now_add=True)
    status     = CharField(choices=['present', 'late', 'absent'], default='present')

    class Meta:

```

**Key concepts:**
- **`Session.record_end()`** — Automatically updates the session's end time and calculates the session's duration.
- **`Attendance.unique_together`** — Prevents duplicate scan records for the same student, course, and date at the database level.
- **Denormalized `course` in `Attendance`** — Saves expensive `JOIN` statements when listing attendance.

```python
class AdminStudentSerializer(serializers.ModelSerializer):
    username = serializers.CharField(write_only=True, required=False)
    password = serializers.CharField(write_only=True)

    class Meta:
        model = Student
        fields = ['id', 'student_id', 'name', 'department', 'department_name', 
                  'study_year', 'study_year_name', 'major', 'major_name', 'username', 'password']

    def create(self, validated_data):
        username = validated_data.pop('username', None) or validated_data.get('student_id')
        password = validated_data.pop('password')

        with transaction.atomic(): # atomic block - if profile creation fails, rollback user account
            user = User.objects.create_user(username=username, password=password)
            student = Student.objects.create(user=user, **validated_data)
        return student
```

## 4. Views

### What is a View?

A **View** handles incoming HTTP requests, performs business/database logic, and returns responses.

### APIView with Background Thread ([attendance/views.py](file:///c:/Users/DQA/Ayoub%20Projects/Alarab_attends_system/backend/attendance/views.py))

```python
class SessionCreateView(APIView):
    permission_classes = [IsAuthenticated]

    def post(self, request):
        professor_id = request.data.get('professor_id')
        course_id    = request.data.get('course_id')

        try:
            professor = Professor.objects.get(pk=professor_id)
            course    = Course.objects.get(pk=course_id)
            semester  = Semester.objects.get(is_active=True)

            session = Session.objects.create(
                professor=professor, course=course, semester=semester
            )
            
            # Fire compliance check in a background thread so we do NOT block the response
            assignment = CourseAssignment.objects.filter(
                professor=professor, course=course, semester=semester
            ).first()
            if assignment:
                from courses.tracking_service import check_and_notify
                t = threading.Thread(target=check_and_notify, args=(assignment,), daemon=True)
                t.start()

            return Response(SessionSerializer(session).data, status=201)
        except Exception as e:
            return Response({'error': str(e)}, status=400)
```

**HTTP Status Codes you'll see:**
- `200 OK` — Action succeeded
- `201 Created` — New record created (e.g. Session created)
- `400 Bad Request` — Client error (validation failed)
- `401 Unauthorized` — JWT token missing or expired
- `403 Forbidden` — Authenticated but lack authorization (e.g. student calling Admin endpoint)
- `404 Not Found` — Resource doesn't exist

## 6. Authentication & JWT

The system uses **Simple JWT** to authenticate requests in a stateless manner.

- **Access Token**: valid for **8 hours**. Sent in headers as `Authorization: Bearer <token>`.
- **Refresh Token**: valid for **7 days**. Used to request new access tokens.
- **PBKDF2 Password Hashing**: Django hashes passwords with 260,000 iterations + a salt. Brute-forcing is computationally infeasible.

## 7. Permissions

Django runs check filters before accessing views:
```
Request arrives ──► Decoded JWT User ──► Permission Classes Check ──► View Code runs
```

- **`AllowAny`** — public views (e.g. log in, public lists).
- **`IsAuthenticated`** — default fallback. The user must provide a valid JWT access token.
- **`IsAdminUser`** — restricted to accounts with `is_staff` or `is_superuser` privileges.

## 8. Caching with Redis

Redis caches high-load validation queries to protect PostgreSQL from connection exhaustion:

```
Without Cache:
  200 Student Scans ──► 200 Database Queries to find Session ──► DB Overload

With Cache:
  Student #1 Scan   ──► DB Query ──► Cached in Redis (15m)
  Scans #2 - 200    ──► Read Redis Cache ──► 0 DB Queries ──► Instant Speed (1ms)
```

In `record_attendance`, the session metadata (expires_at, course_id, semester_id, and quota) is stored in the cache key `session_qr_<qr_token>` for 15 minutes.

## 9. The QR Scan Service

This is the system's scanning engine located in [attendance/services.py](file:///c:/Users/DQA/Ayoub%20Projects/Alarab_attends_system/backend/attendance/services.py). Here is the flow of the `record_attendance` function:

```python
def record_attendance(student_id: str, qr_token: str, device_id: str | None = None) -> dict:
    now = timezone.now()

    # ── 1. Fast Cache Fetch ──
    cache_key = f"session_qr_{qr_token}"
    session_data = cache.get(cache_key)

    if not session_data:
        # Cache Miss: Fetch Session from DB + verify active semester and assignments
        session = Session.objects.select_related('course', 'semester').get(qr_token=qr_token)
        active_semester = Semester.objects.get(is_active=True)
        # Check active semester matches session semester
        if session.semester_id != active_semester.id:
            return {'success': False, 'error': 'Session does not belong to the active semester.'}
        
        session_data = {
            'session_id': session.id,
            'course_id': session.course_id,
            'semester_id': active_semester.id,
            'expires_at': session.qr_expires_at,
            'quota': active_semester.total_lectures
        }
        cache.set(cache_key, session_data, 900)

    # ── 2. Expiration Verification ──
    if session_data['expires_at'] <= now:
        return {'success': False, 'error': 'This QR code has expired.'}

    # ── 3. Student & Enrollment Check ──
    student = Student.objects.filter(
        student_id=student_id,
        enrollments__course_id=session_data['course_id'],
        enrollments__semester_id=session_data['semester_id']
    ).select_related('user').only('id', 'name', 'user_id').first()

    if not student:
        return {'success': False, 'error': 'Student not found or not enrolled.'}

    # ── 4. Device Fingerprint (Anti-Proxy Lock) ──
    if device_id and student.user_id:
        try:
            linked_device = UserDevice.objects.get(user_id=student.user_id)
            if linked_device.device_fingerprint != device_id:
                return {'success': False, 'device_mismatch': True, 'error': 'Unrecognised device.'}
        except UserDevice.DoesNotExist:
            # Device not registered yet - link it (verify no other student uses it)
            if UserDevice.objects.filter(device_fingerprint=device_id).exists():
                return {'success': False, 'device_mismatch': True, 'error': 'Device already used.'}
            UserDevice.objects.create(user_id=student.user_id, device_fingerprint=device_id)

    # ── 5. Lecture Quota Verification ──
    scans_count = Attendance.objects.filter(
        student_id=student.id, course_id=session_data['course_id'], session__semester_id=session_data['semester_id']
    ).count()
    if scans_count >= session_data['quota']:
        return {'success': False, 'error': 'Maximum attendance limit reached.'}

    # ── 6. Insert Attendance with Constraint Guard ──
    try:
        attendance = Attendance.objects.create(
            session_id=session_data['session_id'], student_id=student.id,
            course_id=session_data['course_id'], status='present'
        )
    except IntegrityError:
        return {'success': False, 'error': 'You have already registered your attendance for this lecture.'}

    return {
        'success': True,
        'message': f'Attendance recorded for {student.name}.',
        'attendance_id': attendance.id,
        'scans_used': scans_count + 1,
        'scans_remaining': session_data['quota'] - (scans_count + 1)
    }
```

## 10. Best Practices Used in This Project

| Technique | Where Used | Why It's Good |
|---|---|---|
| **`select_related` / `prefetch_related`** | Views & ViewSets | Pre-fetches foreign keys / relations, solving the N+1 query issue. |
| **`db_index=True`** | Model Fields | Creates DB indexes on lookup keys (e.g. `qr_token`), speeding queries up by 100x. |
| **`unique_together`** | Models Meta | Protects database consistency against race conditions (e.g. duplicate scans). |
| **`transaction.atomic()`** | Serializers & ViewSets | Guarantees that multiple related operations succeed or fail together. |
| **Device Fingerprinting** | `record_attendance` | Solves student proxying by locking attendance to a single browser fingerprint. |
| **Redis Cache-Aside** | `record_attendance` | Caches validated Session attributes, offloading PostgreSQL. |
| **Background Threading** | `SessionCreateView` | Delegates compliance notifications to separate threads without delaying the client. |
| **Persistent Connections** | DB Settings (`CONN_MAX_AGE`) | Keeps database sockets open for 10 minutes, avoiding connection overhead. |
| **`only()` / `defer()` optimization** | Database Queries | Loads only query columns needed for evaluation, reducing system memory load. |

## Final Summary — The Request Lifecycle

Let's trace one complete request: **A student scans a QR code**

1. **Scan QR**: Student's phone camera scans the QR code and extracts the `qr_token` UUID.
2. **API Call**: React client POSTs to `/api/attendance/attendance/scan/` with `student_id`, `qr_token`, and the browser fingerprint `device_id`.
3. **Routing & JWT auth**: Nginx forwards request to Gunicorn, Simple JWT middleware validates headers and decodes student `User`.
4. **Service Check**: Views dispatch request to `record_attendance()` service:
   - **Cache hit check**: Fetch token meta from Redis cache.
   - **Validation check**: Verify token expiration date and enrollment limits.
   - **Device check**: Confirm the current browser fingerprint matches the registered device.
   - **Quota check**: Confirm total scans are below the active semester quota limit.
5. **Database Transaction**: Attempt insertion into `Attendance`.
   - If a record for the student/course/date already exists, catch `IntegrityError` and output a "Duplicated Scan" warning.
   - If clean, commit insert.
6. **HTTP Response**: Returns `200 OK` with remaining semester scans or `403/400` error message.
7. **Feedback View**: Student phone screen confirms attendance registration.
